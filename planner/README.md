# День — личный ежедневник

Приложение: https://sayanovvg.github.io/Time/planner/

Задачи, календарь и заметки дня с общими данными для телефона и помощника в чате. Тёмная тема, мягкая анимация, управление большим пальцем, локальные шрифты и работа с сохранёнными данными без сети.

## Что есть

- Быстрое добавление: `Позвонить поставщику завтра в 16:00 !3 #Бизнес`. Перед сохранением видны распознанные дата, время, приоритет и проект.
- Сегодня, входящие без даты, все задачи, проекты, поиск, архив выполненного.
- Календарь месяца и недели; расписание дня с блоками времени. Пересекающиеся блоки видны рядом. На телефоне время и дату удобно менять в карточке.
- Отдельные плановая дата и крайний срок. Просроченное остаётся доступным; можно перенести или закрыть прошлую задачу.
- Повторения: каждый день, по будням, по неделям, месяцам и годам, с интервалом и датой окончания.
- Чек-листы, заметки, метки, приоритеты, выделение главных дел, матрица важности и срочности.
- Заметка каждого дня, длительность задач, ориентир нагрузки на день, таймер фокуса и перерывы.
- Резервная копия JSON, восстановление и экспорт расписания ICS для календарей.

У календарного экспорта нет автоматической двусторонней связи с Google Calendar. Надёжные фоновые push-напоминания не включены. Звук таймера зависит от ограничений мобильного браузера.

## Первый вход

Открыть личную одноразовую ссылку из чата, указать свою почту и придумать пароль от 12 символов. Подтверждение по почте для этого приглашения не требуется. Повторные входы — по той же почте и паролю в «Настройки и связь». Пароль вводится только в приложении.

Приглашение разрешает создать один новый аккаунт; оно не даёт доступа к существующему. Секрет ссылки хранится в базе только в виде SHA-256, имеет срок действия и расходуется атомарно. Ссылка не публикуется в репозитории. Если первый запрос завершился с ошибкой сети после создания аккаунта, следует попробовать обычный вход.

Можно пользоваться локально без входа. После подключения кнопка «Перенести записи с телефона» переносит эти записи в аккаунт. Входящие облачные записи появляются через Realtime; резервное обновление — при возврате в приложение и каждые 15 секунд открытой вкладки.

## Сохранение и конфликты

IndexedDB сохраняет каждое действие и очередь отправки в одной транзакции, отдельно для каждого аккаунта. Сервер применяет пакет целиком. Повтор запроса с тем же номером безопасен: он возвращает прежний результат. Версия записи защищает от перезаписи свежих изменений устаревшими. При конфликте сохраняются оба варианта до явного выбора в настройках.

При закрытии просроченного повторения создаётся только следующая актуальная дата; пропущенные даты не записываются как выполненные. Отмена закрытия убирает автоматически созданное следующее повторение, только если оно ещё не было изменено.

Шаблоны проектов — «Бизнес», «Личное», «Здоровье». Демонстрационных пользовательских задач нет. Дата и время соответствуют часовому поясу устройства; он сохраняется в профиле для помощника.

Это самостоятельная реализация выбранных рабочих приёмов, со своим интерфейсом и кодом.

## Разработка и публикация

Исходный проект находится в ветке `daily-planner`. Статические файлы из `planner-dist/` публикуются только в `main/planner/`; корневой MAX TIME и `main/habits/` сохраняются.

```sh
pnpm install --frozen-lockfile
pnpm test:planner
pnpm exec tsc --noEmit
pnpm build:planner
```

Supabase JS зафиксирован на 2.115.0. В `planner/public/sync-config.json` только публичный ключ. Секретные ключи администратора не должны попадать в клиент, резервные копии или git.

Миграции `backend/001_planner.sql`, `002_validate_contract.sql`, `003_private_setup.sql`, `004_unambiguous_batch.sql` применяются по порядку через Supabase migrations. Edge Function `planner-activate` использует собственную проверку одноразового секрета; поэтому только у неё `verify_jwt=false`. Её стандартный `SUPABASE_SERVICE_ROLE_KEY` используется исключительно на сервере. Все помощники с повышенными правами находятся в закрытой схеме `planner_private`; публичные SQL RPC — обычные обёртки с точными разрешениями.

Таблица `planner_records` доступна на чтение только владельцу через RLS. Прямые клиентские изменения запрещены; RPC получает владельца из проверенной сессии. Журнал операций и приглашения закрыты для пользовательских ролей.

Тесты модели покрывают даты, повторения, отмену, очередь при потере ответа, одновременные правки, конфликты и повреждённые копии. `tests/cloud-smoke.py` — отдельный интеграционный сценарий с двумя временными аккаунтами и обязательной очисткой: вход, ограничения RLS, повторы запросов, конфликт целого пакета, проверка данных и изменение помощником, видимое через тот же API, что использует телефон. Он требует административного применения сгенерированного SQL и не запускается обычным `test:planner`.

Инструкции помощнику: [ASSISTANT.md](ASSISTANT.md).

При проверке Supabase не обнаружены замечания к изоляции данных ежедневника. В существующем проекте выключена дополнительная [проверка паролей по базам утечек](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Параметры других приложений не менялись.
