# Работа Макса с ежедневником

Пользователь просил отправлять согласованные задачи из чата прямо в свой ежедневник. Использовать подключённый Supabase, проект `ophvfvhuuxjbbkdongfu` (`iibrain-secretary`, организация IIBRAIN). Приложение: `https://sayanovvg.github.io/Time/planner/`. Исходники: `SayanovVG/Time`, ветка `daily-planner`. Не использовать старые локальные данные трекера привычек или другие таблицы бизнеса.

## Определение владельца

Нельзя угадывать адрес или выбирать первый случайный аккаунт. Сначала прочитать завершённое личное подключение и часовой пояс:

```sql
select u.id, u.email, u.raw_user_meta_data->>'planner_timezone' as timezone
from planner_private.setup_links l
join auth.users u on u.id=l.owner_id
where l.claimed_at is not null
order by l.claimed_at;
```

Если имеется один активированный аккаунт в этом личном проекте — использовать его. Если их несколько, сопоставить с известным адресом пользователя; при неоднозначности уточнить почту. Никогда не читать пароль, хэш пароля, токены подтверждения или сессий. Если вход не завершён, честно сказать, что облачного аккаунта ещё нет; не писать задачи чужому владельцу.

## Чтение и запись

Читайте только записи нужного владельца:

```sql
select id,kind,body,revision,deleted,updated_at,updated_by
from public.planner_records where owner_id='<resolved UUID>' and not deleted;
```

Задача — запись `kind='task'`. Её полный формат и ограничения находятся в `lib/model.ts` (`Task`, `blankTask`, `validateBody`), логика повторений — `completionChanges`. Сохраняйте незатронутые поля при правках. Встроенные проекты: `business`, `personal`, `health`; `inbox` означает отсутствие проекта. Приоритет 3 — высокий, 0 — без приоритета. Дата `YYYY-MM-DD` и время `HH:mm` — в часовом поясе телефона из профиля, а `createdAt`, `updatedAt`, `completedAt` — ISO со смещением/UTC. Если часовой пояс пока неизвестен, не угадывать время конкретного события.

Использовать только административный помощник, доступный через подключённый инструмент SQL:

```sql
select planner_private.planner_assistant_commit(
  '<resolved email>',
  '<unique operation UUID>'::uuid,
  '[{"id":"<record UUID>","kind":"task","body":{...full validated Task...},"deleted":false,"base_revision":0}]'::jsonb
);
```

Для новой задачи `base_revision=0`, для правки/удаления — последняя прочитанная `revision`. Для новой задачи `source='max'`. Для правок существующей задачи происхождение можно оставить исходным; `updated_by='max'` выставляется сервером. Удаление — tombstone `deleted=true`, с текущим body. Не удалять физически пользовательские записи.

Одной операцией можно записать до 100 изменений. На случай потери ответа сохранить исходный UUID операции и точный payload и повторить их без изменения. Иначе возможен дубль. Ответ `status='conflict'` означает, что ни одна запись пакета не была применена. Перечитать, сохранить новые пользовательские поля, затем составить новую операцию; не объявлять успех до ответа `ok` и контрольного чтения. SQL-текст формировать безопасно, с параметрами или корректным SQL-экранированием строк, никогда не через shell-интерполяцию пользовательского текста.

После записи подтвердить название, локальную дату/время и результат. Телефон подтягивает изменения через Realtime, при открытии и по резервному таймеру 15 секунд. «Записано в общую базу» не означает, что офлайн-телефон уже получил изменение.

Не создавать новые задачи из случайных упоминаний или выдуманных сроков. Выполнять явные просьбы «добавь в ежедневник» и согласованные в разговоре планы в рамках действующей просьбы пользователя. Не обещать перенос всех будущих сообщений без доступного подключения. Экспорт ICS — разовая копия; Google Calendar не синхронизируется автоматически. Фоновых push-уведомлений нет.

## Новая ссылка подключения

Нужна только для первого аккаунта; не создавайте второй вместо существующего и не используйте её для сброса чужого пароля. При подтверждённой необходимости генерировать криптографически случайный токен 32 байта, кодировать base64url без padding (43 символа), вставить только его SHA-256 в `planner_private.setup_links` с ограниченным `expires_at`. Старое неиспользованное приглашение можно отозвать точным хэшем. Дать владельцу приватную ссылку `https://sayanovvg.github.io/Time/planner/#connect=<token>`. Не сохранять сам токен, ссылку или пароль в публичный git, документы или журналы. Наличие хэша не является авторизацией; Edge Function проверяет сам секрет и атомарно расходует приглашение до создания аккаунта через Auth Admin API.

Если аккаунт создан, но у setup_links не появился owner_id после сетевой ошибки, сопоставить его только с подтверждённой пользователем почтой и проверить app_metadata.planner; не присваивать владение по случайному совпадению.
