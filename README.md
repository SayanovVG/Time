# MAX TIME 3.0

Личный журнал тренировок, питания и прогресса. Сохраняет текущую программу из пяти дней, идентификаторы упражнений и режим без MMA.

## Что изменилось

- Единое приложение вместо слоёв скриптов, переопределяющих друг друга. Старые файлы оставлены для безопасного перехода уже установленных копий.
- Проверка резервной копии **до записи**, полный экспорт и шесть автокопий предыдущих состояний. Ошибки места в хранилище видны; неудачная запись не меняет журнал в памяти. Защита от перезаписи из второй вкладки.
- Питание в отчёте рассчитывается по дневнику. Средние — только по явно завершённым дням. Пустые и будущие дни не искажают статистику.
- Фактические порции в шаблонах еды, яйца в штуках, десятичная запятая и проверка количества. Старые записанные калории сохраняются; новые порции рассчитываются по продуктам.
- История тренировок по датам, видимые прошлые отметки, корректный RIR 3+, проверка подхода перед завершением и сохранение значений, находящихся в полях.
- Таймер по времени окончания, восстановление активного таймера в той же вкладке. Длительности упражнения и отдыха сохраняются отдельно. Звук синтезируется на устройстве.
- Более крупный Manrope, локальные файлы шрифта, контрастные поля, кнопки от 44 px, нижняя навигация на телефоне, подписи полей, нативные диалоги, разрешённый масштаб. Короткие анимации отключаются через `prefers-reduced-motion`.
- Офлайн-кеш включает весь активный интерфейс. Обновление применяется по кнопке; кеши соседнего приложения «Два кота» не удаляются. В его трёх service worker также ограничена очистка собственными именами.

## Данные и обновление

Старый ключ `max_time_v2` читается, но **не перезаписывается и не удаляется**. Новые изменения сохраняются в `max_time_v3`. Неизвестные поля старого состояния сохраняются в экспорте. Исходный повреждённый журнал можно скачать с экрана восстановления.

Одинаковые записи одной недели, похожие на копии старого механизма переноса, остаются в данных, но учитываются один раз. Решение можно отменить в разделе «Сохранность данных». Начальный замер 84 кг / 100 см требует подтверждения, поскольку старая версия создавала его автоматически.

Полный экспорт: **Прогресс → Экспорт**. Его нужно хранить вне браузера: локальные автокопии не защищают от потери устройства или удаления данных сайта. Старые частичные автокопии v46 остаются в старом хранилище и доступны прежней версии; новый импорт принимает старые полные экспорты.

Новая версия сохраняет PWA `id`, `start_url` и область действия. При обновлении установленного приложения может потребоваться закрыть все его окна и открыть снова. Не очищайте данные сайта для обновления.

## Разработка и проверки

Node.js 24:

```sh
npm ci
npm run dev
npm run check
npm test
```

Vite нужен для разработки, а не для размещения на GitHub Pages. Активные файлы находятся в `app/`; обе HTML-страницы загружают `app/main.mjs`. Программа — `app/program.mjs`, правила данных и расчёты — `app/model.mjs`, хранение — `app/store.mjs`.

Проверки запускаются также в GitHub Actions. Сценарии включают повреждённый импорт, переполнение хранилища, две вкладки, полный откат, RIR, календарные границы, совпадение дневника и отчёта, старую миграцию, таймер и изоляцию офлайн-кешей. `tests/fixtures/legacy-clean.json` получен из чистого запуска прежних скриптов; это синтетический журнал, не данные владельца.

Для ручной проверки размеров: `tests/viewport.html`. На предпросмотре service worker отключён, чтобы не мешать разработке. Проверка офлайн-кеша выполняется отдельно в `tests/offline.test.mjs`.

## Проверено перед передачей

- 24 автоматических сценария: пройдены.
- В браузере: ввод и завершение подхода, RIR 3+, сохранение после перезагрузки, изменение отдыха, отдельная настройка таймера планки, прошлые даты, ручной переход назад в тренировке, поиск еды, яйца в штуках, завершение дня и отчёт с совпадающими калориями.
- Интерфейс просмотрен на широком экране и в окнах 393 и 320 px. На узком экране нет горизонтальной прокрутки и видимых полей/кнопок меньше 44 px.

Физический Redmi, установленная PWA, громкость сигнала и поведение при блокировке телефона требуют проверки на самом устройстве. Браузер может приостановить выполнение в фоне: остаток времени пересчитывается верно при возвращении, но точный момент звукового сигнала на заблокированном телефоне не гарантируется.
