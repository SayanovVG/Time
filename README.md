# Ритм — трекер привычек

Личный трекер на русском: тёмный дизайн, цветные привычки, анимация отметок и удобное заполнение прошлых дней. Интерфейс адаптирован для телефона, шрифт Manrope загружается вместе с приложением.

**Открыть:** https://sayanovvg.github.io/Time/habits/

Исходный код находится в ветке `habit-tracker` репозитория `SayanovVG/Time`. Собранная версия публикуется в каталоге `habits/` основной ветки, рядом с MAX TIME.

## Как пользоваться

1. Нажми «Новая привычка» (кнопка «+» на телефоне), выбери название, значок, цвет и дату начала.
2. Выбери день в полосе недели или календаре и поставь галочку. Можно вернуться к любой прошлой дате.
3. Если пропустил несколько дней, нажми «Заполнить дни» у привычки: отметь даты, при необходимости переключи месяц и сохрани всё одним действием.
4. Повторное нажатие снимает отметку. Будущие дни недоступны.
5. Меню «…» позволяет изменить или удалить привычку. Удаление всей её истории требует подтверждения.

## На телефоне

Привычки и отметки хранятся в IndexedDB **этого браузера на этом устройстве**. Учётная запись не нужна. Данные не отправляются в GitHub и не синхронизируются с другим телефоном или браузером. Запись считается сохранённой только после успешного завершения транзакции; ошибка хранения показывается в интерфейсе. Параллельные вкладки читают свежие данные перед записью.

В верхнем меню резервных копий можно скачать JSON-файл или восстановить его. Восстановление проверяет файл и после подтверждения заменяет текущие привычки и отметки. Перед очисткой браузера или сменой телефона скачай копию. В приватной вкладке браузер может удалить данные при закрытии.

После первой успешной загрузки и установки служебного кеша трекер открывается без интернета. Шрифты и интерфейс находятся на том же адресе. Обновление кеша не удаляет привычки и не затрагивает кеш MAX TIME. Доступность первой загрузки без VPN зависит от сети пользователя.

## Логика прогресса

- Дни хранятся как `YYYY-MM-DD`; «сегодня» определяется по часовому поясу устройства, без преобразования дня в UTC.
- Отметка раньше даты начала сдвигает начало назад. Редактирование даты начала сохраняет существующие отметки.
- Процент месяца — выполненные отметки / ожидаемые отметки с начала каждой привычки до сегодняшнего дня включительно. Будущие дни не входят в расчёт.
- Идеальный день — выполнены все привычки, начавшиеся к этому дню. Пустой день не считается идеальным.
- Текущая серия учитывает непрерывные выполненные дни; незавершённый сегодняшний день пока не обрывает её.
- Заполнение пропуска сразу пересчитывает серию и статистику.
- Пределы локальной версии: 500 привычек, 100 000 отметок и до 366 изменений в одном сохранении. Файл восстановления — до 12 МБ.

## Сборка для GitHub Pages

Требуются Node.js >=22.13.0 и версия pnpm из `package.json`.

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm exec tsc --noEmit
pnpm build:pages
```

Результат — каталог `github-pages/`. Для публикации его содержимое копируется в `habits/` основной ветки существующего репозитория с настроенным GitHub Pages. Не заменяй корень сайта: там размещён MAX TIME. Ссылки на ресурсы и область service worker относительные; серверные API, ключи и база данных для этой версии не нужны.

Исходники: `pages/main.tsx` — вход локальной версии, `app/tracker.tsx` — интерфейс, `app/globals.css` — дизайн, `lib/habits.ts` — даты и статистика, `lib/local-data.ts` — изменения и резервные копии, `lib/local-store.ts` — транзакционное хранение, `scripts/prepare-pages.mjs` — офлайн-кеш и манифест.

## Прежняя серверная версия

В ветке сохранена исходная серверная конфигурация Sites/Vinext/D1. Команды `pnpm dev` и `pnpm build` относятся к ней. Она не используется при сборке `build:pages` и не является источником данных новой версии. При переносе обе таблицы старого экземпляра были пусты.

Серверная авторизация доверяет заголовкам платформы Sites только за её шлюзом; этот API нельзя выставлять на другом хостинге без собственной аутентификации. `.openai/hosting.json` сохраняет идентичность старого экземпляра, а не настраивает GitHub Pages.

## Проверка

Автоматические тесты покрывают календарные границы, високосные даты, серии после заполнения пропуска, статистику без будущих дней, экспорт и восстановление, повторные отметки без дубликатов, отклонение повреждённого файла и сохранение исходных данных при ошибке пакетного изменения. Проверяются TypeScript и производственная сборка.

Браузерная проверка на реальном телефоне не выполнялась. WebMCP необязателен: обычные элементы управления работают без него.
